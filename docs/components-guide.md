# AIRA Web Components Guide

`aira-web-components` is a plain Java library for rendering the common AIRA application shell around servlet-generated page content.

It generates the document head, shared stylesheet link, optional local stylesheet links, skip navigation, header, identity, primary navigation, opening main container, optional page heading and intro text, required institutional footer, and closing document structure.

## Composition, Not a Base Servlet

The library does not provide a base servlet. Applications keep their own servlet classes and compose the renderer where they write the response. This avoids coupling branding to servlet lifecycle, sessions, authentication, or application initialization.

## Maven Dependency

```xml
<dependency>
  <groupId>org.immregistries</groupId>
  <artifactId>aira-web-components</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

`aira-web-components` depends on `aira-web-theme`, so the theme resources are included transitively in the WAR under `WEB-INF/lib`.

## Minimal Servlet Usage

```java
AiraPage page = AiraPage.builder()
    .applicationName("Example Application")
    .applicationVersion(applicationVersion)
    .documentTitle("Example Application")
    .pageHeading("Dashboard")
    .pageIntro("Operational summary for the application.")
    .contextPath(request.getContextPath())
    .addNavigationItem("Home", "/", true)
    .addNavigationItem("Reports", "/reports", false)
    .addLocalStylesheet("/css/application.css")
    .build();

page.writeStart(writer);
renderApplicationContent(writer);
page.writeEnd(writer);
```

## Context Paths

Pass `request.getContextPath()` to `contextPath(...)`. Application-relative paths such as `/css/application.css`, `/reports`, and `/` are resolved correctly for both an empty context path and a deployed context such as `/aira-web-demo`.

Absolute `http://` and `https://` URLs are left unchanged. Fragment links such as `#form-demo` are also left unchanged.

## Stylesheets

The renderer always writes the shared stylesheet first:

```html
{contextPath}/aira/css/aira.css
```

Local stylesheets added with `addLocalStylesheet(...)` are rendered afterward. Local CSS should remain application-specific and should not duplicate the shared theme.

## Navigation

Add primary navigation with `addNavigationItem(label, href, active)`. When `active` is true, the link receives `aria-current="page"`. If no navigation items are supplied, the `<nav>` element is omitted.

## Application Identity and Logo

Set the application name and optional subtitle in the builder. If no approved logo is configured, the header uses restrained text identity and emits a comment marking where an approved AIRA logo can later be placed.

When an approved logo asset is available, configure it with `new AiraLogo(source, alternativeText)`. Do not redraw or approximate the AIRA logo.

## Footer

The required institutional footer is generated by the component library. Defaults include the AIRA website URL, privacy policy URL, terms of use URL, institutional description, current year, application name, and application version.

Override legal URLs explicitly with `AiraFooterConfig.builder()` only when an application has an approved need to do so. The copyright year can also be overridden for deterministic tests.

## Escaping

All text and attribute values accepted by the shared renderers are HTML escaped. The library accepts plain text for its own fields; it does not sanitize arbitrary application-provided HTML.

Applications remain responsible for safely generating and escaping their page-specific content.

## Deliberately Not Included

This stage does not include a shared base servlet, authentication hooks, session handling, JavaScript, buttons, forms, tables, dialogs, or data-grid renderers. Those can be designed later if repeated application needs justify them.
