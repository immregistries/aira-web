# AIRA Web Adoption Guide

This guide explains how Java Servlet applications can adopt shared AIRA web resources.

## Maven Dependencies

Use `aira-web-theme` when an application only needs shared static resources:

```xml
<dependency>
  <groupId>org.immregistries</groupId>
  <artifactId>aira-web-theme</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

Use `aira-web-components` when an application also wants the generated AIRA shell:

```xml
<dependency>
  <groupId>org.immregistries</groupId>
  <artifactId>aira-web-components</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

`aira-web-components` depends on `aira-web-theme`, so the CSS is included transitively.

## Resource Loading

Servlet containers expose static resources found in dependency JARs under `META-INF/resources`.

The theme JAR contains:

```text
META-INF/resources/aira/css/aira.css
```

When the JAR is in `WEB-INF/lib`, request:

```text
{contextPath}/aira/css/aira.css
```

Load application CSS after the shared theme:

```html
<link rel="stylesheet" href="{contextPath}/aira/css/aira.css">
<link rel="stylesheet" href="{contextPath}/css/application.css">
```

## Recommended Shell Structure

The first-release shell is:

1. Skip link.
2. Global header with AIRA identity, app name/subtitle, optional search, optional global actions, optional account/sign-in area, and optional environment badge.
3. Optional contextual header with a contextual title and navigation.
4. Main content generated by the application.
5. Required institutional footer.

Use the Java renderer when possible so the shell is consistent:

```java
AiraPage page = AiraPage.builder()
    .applicationName("InteropHub")
    .applicationSubtitle("Collaboration workspace")
    .applicationVersion(applicationVersion)
    .documentTitle("Topics - InteropHub")
    .contextPath(request.getContextPath())
    .identityHref("/")
    .search(new AiraSearchConfig("/search", "q", "Search", "Search topics"))
    .addGlobalAction("Explore", "/", "secondary")
    .account(new AiraAccountConfig("Signed in user", "Account", "/account"))
    .environment(new AiraEnvironmentConfig("Test", "Test environment"))
    .context(new AiraContextConfig("Emerging Standards for Immunizations", List.of(
        new AiraNavigationItem("Home", "/", false),
        new AiraNavigationItem("Topics", "/topics", true),
        new AiraNavigationItem("Meetings", "/meetings", false))))
    .addLocalStylesheet("/css/application.css")
    .build();

page.writeStart(writer);
renderApplicationContent(writer);
page.writeEnd(writer);
```

## Shared CSS Contract

The stable public CSS contract is the `aira-` class namespace and the CSS custom properties. The theme provides component categories for shell, layout, typography, buttons, forms, badges, cards, choice rows, event lists, tables, alerts, management layouts, footer, and small utilities.

Applications may add local classes for domain-specific composition. They should not duplicate or redefine the shared shell, footer, brand tokens, button system, form controls, or table baseline.

## Application-Specific Behavior

AIRA Web does not implement JavaScript interactions, authentication, routing, form processing, menu behavior, dialogs, bottom sheets, drag-and-drop, or domain rules. Use native HTML controls where possible and layer application behavior separately.

## Upgrades

Consume versioned Maven artifacts and upgrade intentionally. Review release notes, run tests, and inspect desktop and narrow-width layouts before deploying an application with a new AIRA Web version.
